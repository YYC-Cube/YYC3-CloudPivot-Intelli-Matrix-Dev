## 三、五大致命发现（详细证据见分报告）

### 发现 1 · family-* 双真相源（最高危架构矛盾）

`pnpm-workspace.yaml` 排除根 `packages/family-*`、纳入 `docs/packages/*` 并称其为「权威实现」——但根 `pnpm test`/`tsc` 经由 vitest alias / tsconfig paths 跑在**根镜像**上。结果：

- **运行时**：plugin-ai-family → docs/packages/family-core/dist（CJS 产物）
- **质量门禁**：测的是根镜像（6+10 测试），docs 权威版的 799 测试**不在任何 CI 内**
- family-agents 两侧已结构性分叉（自足版 vs 继承 BaseAgent 版），漂移已兑现

**修复方向**：二选一确立唯一权威（建议：根目录升位为唯一源，docs 降为产物；或反向——把 docs 三包移出 docs/ 正名为核心包），补 CI 对权威侧的测试覆盖。

### 发现 2 · 部署链 4 个阻断级断点

1. Dockerfile COPY 不存在的 `plugin-dynasty` → docker build 必挂
2. pnpm 版本矛盾（workspace 用 11+ 语法、CI/Docker 钉 9.15.0）→ frozen install 必挂
3. CI deploy needs 链含 PR-only 的 lighthouse → main push 永不部署
4. Vercel buildCommand 含 `pnpm test`（install 先挂，同源 B2）

**修复成本**：半天，全是小改（详见 03 报告第六节分阶段路线）。

### 发现 3 · README/规划文档数字体系失真

「799 tests」「996 合计」「80+261 技能」均无法复现；「Phase 4 生产部署 100% ✅」实况是部署链断点未修；规划文档的技术栈清单（openai npm/dexie/crypto-js）与实际（零依赖自研）完全不符。**文档信任度是当前最大的隐性成本**——任何基于 README 的决策都会踩坑。

### 发现 4 · 「插件化架构」契约未闭环

`SystemRegistration` 契约（register()）全仓无消费者，`routes: []` 空壳，full 的路由靠手写 lazy import。六个界面型插件（monitor/ops/ai/business/dev/admin）是 58–110 行的占位单页、零测试、硬编码 mock 数据。「同一底座多形态交付」实况 = 只有 shell 一层被复用。

### 发现 5 · 优质资产真实存在（不必悲观)

- **plugin-llm**（1,653 行 + 57 测试）：5 Provider + SSE + AES-256-GCM Keyring + 成本路由，**零框架依赖**，1-2 人日可独立发包
- **四大业务引擎**（target/cost/marketing/prompt）：纯函数、125 测试护航，但未接入任何 app——「孤岛库」
- **family-core 宪章 + PDAMR 骨架**：人格档案 schema 与认知环抽象优秀（智能层是关键词规则，需自接 LLM）
- **shell 核心层**（EventBus/Storage/Theme/ErrorBoundary 约 360 行核心零外部依赖）
- TypeScript strict 全域零错误是真金白银的质量信号

### 多用场景速配

- **要 LLM 能力** → 抽 plugin-llm + api/chat/stream.ts（服务端形态）+ llm-bridge.ts（应用层封装参考）
- **要 AI 浮窗** → cp -r 根目录 AIAssistant/（官方支持用法）或 docs/packages/ai-assistant（包化版）
- **要管理后台底座** → shell + SystemRegistration 契约 + 补 SystemRegistry（0.5-1 天）
- **要智能体家族** → family-core 宪章 + family-agents PDAMR + family-skills 注册表，智能层接 plugin-llm
- **要行业计算** → 四大引擎按需取用，LunarEngine（零依赖农历 2024-2030）是隐藏亮点
